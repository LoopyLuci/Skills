# WebBuilder Desktop App — Session Notes (2026-08-23)

## Key Decisions

1. **PyQt5 over Electron**: Electron had binary download issues. PyQt5 with PyQtWebEngine provides native performance and reliable GUI.

2. **Flask backend**: Chosen over Python http.server for proper REST API, JWT auth, SQLite persistence, rate limiting, and security headers.

3. **12 providers**: 8 cloud + 4 local. Local providers (Ollama, Unsloth, LLM Studio, LM Studio) are always "configured" since they run locally.

4. **Free-first sorting**: Free/local models appear at the top of the model list, paid models below with visual separators.

5. **Threading**: AI API calls run in background threads to prevent UI blocking. UI re-enablement uses QTimer.singleShot for thread safety.

## Technical Issues Solved

### 1. PyQt5 Import Errors
- **Problem**: `from PyQt5.QtWebEngine import QWebEngineSettings` fails
- **Fix**: Use `from PyQt5.QtWebEngine import *` or just import QWebEngineView from.QtWebEngineWidgets

### 2. Circular Imports
- **Problem**: `components.py` imported `Config` from `desktop_app.py` which caused circular import
- **Fix**: Removed import from components.py — Config is defined in desktop_app.py and components.py doesn't need it directly

### 3. ProviderCard Click Events
- **Problem**: Custom QFrame widgets don't have `.clicked` signal
- **Fix**: Override `mousePressEvent` directly with lambda binding: `card.mousePressEvent = lambda event, p=pid: self.configure_provider(p)`

### 4. QFormLayout.addRow on QVBoxLayout
- **Problem**: Using `layout.addRow()` on a QVBoxLayout raises AttributeError
- **Fix**: Use QHBoxLayout inside QVBoxLayout for form-like layouts

### 5. QGridLayout.addStretch
- **Problem**: QGridLayout doesn't have `addStretch()` method
- **Fix**: Use `grid_layout.setRowMinimumHeight(row, 20)` as spacer

### 6. Lambda Capture in Loops
- **Problem**: All lambdas in a loop capture the final value of the loop variable
- **Fix**: Use default parameter binding: `lambda event, p=pid: func(p)`

### 7. API Key Storage
- **Location**: `C:\Users\Server\.webbuilder\config.json`
- **Format**: `{"settings": {...}, "keys": {"openai": "..."}}`
- **Local providers**: No key needed, endpoint URL is the configuration

## API Integration Patterns

### OpenAI-compatible (OpenAI, OpenRouter, Grok, etc.)
```python
headers = {'Authorization': f'Bearer {api_key}'}
payload = {'model': model, 'messages': messages, 'max_tokens': 4096, 'temperature': 0.7}
r = requests.post(endpoint, headers=headers, json=payload, timeout=60)
```

### Anthropic Claude
```python
headers = {'x-api-key': api_key, 'anthropic-version': '2023-06-01'}
payload = {'model': model, 'max_tokens': 4096, 'messages': messages}
```

### Google Gemini
```python
# API key goes in URL query, not header
r = requests.post(f"{endpoint}/{model}:generateContent?key={api_key}", json=payload)
```

### Ollama (Local)
```python
# No auth needed
payload = {'model': model, 'messages': messages, 'stream': False}
r = requests.post('http://localhost:11434/api/chat', json=payload, timeout=120)
```
