# ML design for the pre-compiler

Reference for `docs/ML-DESIGN.md`. Purpose-built AI/ML models for the real-time
Rust pre-compiler, sized for bare-CPU (no GPU dependency) with CPU EP as the floor.

## Sizing table

| ID | Model | Params | CPU latency | CPU RAM | Gain |
|----|-------|--------|-------------|---------|------|
| M1 | Change-impact GNN | ~1.5 M | 3–6 ms | ~10 MB | 10–50× fewer rebuilds (~100:1 ROI) |
| M2 | Latency GBT | 0 (trees) | <1 ms | ~500 KB | kills timeouts |
| M3 | Prefetch GRU | ~0.5 M | 1–2 ms | ~5 MB | warm-hit 5–20× faster |
| M4 | Relevance tiny-transformer | ~3 M | 2–4 ms | ~15 MB | cuts agent context 2–4× |
| M5 | Codefix small-edit NN | ~1.2 M | ~3 ms | ~12 MB | instant fixes (~80% of diagnostics) |
| M6 | Code-classifier (logistic) | ~50 weights | <0.1 ms | ~1 KB | routes to right fixer |
| M7 | Rewriter tiny-seq2seq | ~2 M | 4–6 ms | ~12 MB | faster agent reads |
| M8 | Backend-selector GBT | 0 (trees) | <1 ms | ~400 KB | faster debug builds |
| M9 | Env-policy logistic | ~50 weights | <0.05 ms | ~1 KB | stronger cred guard |
| M10 | Degradation anomaly (EWMA) | 0 (rules+stat) | <0.01 ms | ~1 KB | early warning |
| M11 | Scheduler bandit (LinUCB) | 0 (linear) | <0.1 ms | ~1 KB | smarter queue |

## Key rules

- **CPU-first:** ONNX (`ort`) with CPU Execution Provider as the floor; GPU
  (CUDA/ROCm EP) is optional acceleration, not a dependency.
- **Self-labeling:** the daemon logs `RAAP_QUERY_MS`, diagnostic codes,
  severity/messages, VFS hashes, and subprocess exit codes — training data is
  generated by running the system, not manufactured.
- **M5 split:** common fixes via 1.2 M-param NN (in-process); hard fixes fall
  back to optional 1–3 B GGUF codefix LLM via `llama.cpp` sidecar — strictly opt-in.
- **Every model must improve performance more than it consumes resources.**
  If a model costs 6 ms but saves 100 ms, its ROI is positive. If it costs 50 ms
  to save 20 ms, it must not ship.
